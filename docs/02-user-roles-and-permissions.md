## 사용자 역할 정의

### 1. company_user (기업 사용자)

성장기업으로 선정된 기업 소속 사용자입니다.

**특징:**
- 특정 기업(company)에 소속
- 자신 기업의 데이터만 접근 가능
- 예산서 작성, 구매요청, 환급신청 가능
- 프로그램 참가 신청 가능

**등록 방식:**
- 관리자가 기업 정보 등록 후 초대
- 또는 관리자가 직접 사용자 계정 생성

### 2. individual_user (개인 참가자)

기업에 소속되지 않은 외부 개인 참가자입니다.

**특징:**
- 특정 기업에 소속되지 않음
- 프로그램 참가 신청만 가능
- 예산/구매/환급 기능 사용 불가

**등록 방식:**
- 자가 가입 후 이메일 인증
- 관리자 승인 후 활성화

### 3. admin (운영 관리자)

사업 운영을 담당하는 관리자입니다.

**특징:**
- 자신이 담당하는 사업(program) 데이터 관리
- 예산서 승인, 구매요청 승인, 환급 승인
- 프로그램 운영 및 참가자 관리
- 회사 데이터 수정 권한 없음

### 4. super_admin (최고 관리자)

시스템 전체를 관리하는 최고 권한자입니다.

**특징:**
- 전체 사업, 사용자, 관리자 관리
- 기업 정보 생성/수정
- 관리자 권한 부여
- 시스템 설정 관리
- 가이드라인/FAQ 관리

## 데이터 접근 제어 원칙

### 1. 서버 검증 (필수)

모든 데이터 접근은 반드시 서버에서 검증되어야 합니다.

```typescript
// 예시: Supabase RLS 정책
// 기업 사용자는 자신 기업의 예산만 조회
CREATE POLICY "Users can view own company budgets"
ON budgets FOR SELECT
USING (
  company_id IN (
    SELECT company_id FROM user_companies
    WHERE user_id = auth.uid()
  )
);
```

### 2. RLS 정책 (필수)

모든 업무 테이블에 Row Level Security를 적용합니다.

**RLS 대상 테이블:**
- companies
- budgets
- budget_items
- budget_changes
- purchase_requests
- refund_applications
- programs
- program_applications
- certificates

### 3. 화면 메뉴 숨김 (선택)

UI에서 메뉴를 숨기는 것은 사용자 경험을 위한 추가 조치입니다.
이것만으로는 보안이 충분하지 않습니다.

### 4. 감사 기록

관리자의 중요 작업은 audit log에 기록합니다:

- 예산 승인/반려
- 구매요청 승인/반려
- 환급 승인/반려
- 사용자 권한 변경
- 기업 정보 수정

## 인증 흐름

### 기업 사용자 로그인

```
1. 이메일/비밀번호 입력
2. Supabase Auth 인증
3. user_roles 테이블에서 역할 확인
4. user_companies 테이블에서 소속 기업 확인
5. 세션에 역할/기업 정보 저장
```

### 개인 참가자 로그인

```
1. 이메일/비밀번호 입력
2. Supabase Auth 인증
3. user_roles 테이블에서 individual_user 역할 확인
4. 세션에 역할 정보 저장
```

### 관리자 로그인

```
1. 이메일/비밀번호 입력
2. Supabase Auth 인증
3. user_roles 테이블에서 admin/super_admin 역할 확인
4. admin_programs 테이블에서 담당 사업 확인 (admin만)
5. 세션에 역할/담당사업 정보 저장
```

## 보안 규칙

1. **역할 확인:** 모든 API 요청에서 역할을 검증
2. **소속 확인:** company_user는 항상 자사 데이터만 접근
3. **담당 확인:** admin은 담당 사업 데이터만 접근
4. **권한 상승 방지:** 클라이언트에서 역할 정보 수정 불가
5. **세션 관리:** 역할 변경 시 세션 갱신 필요
