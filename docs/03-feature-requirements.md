## 1. 예산서 작성

### 1.1 기간 관리

**관리자 기능:**
- 예산 작성 기간 설정 (시작일, 종료일)
- 예산 변경 기간 설정 (시작일, 종료일)
- 기간 상태: 대기, 진행중, 종료

**규칙:**
- 기간이 종료되면 기업 사용자는 수정 불가
- 관리자는 항상 수정 가능 (단, 사유 기록 필요)
- 기간 설정은 사업(program) 단위

### 1.2 예산서 작성

**작성자:**
- 기업 사용자 (자사 예산)
- 관리자 (대신 작성 가능)

**필수 정보:**
- 사업 (program)
- 기업 (company)
- 회계연도
- 작성자
- 작성 방법 (본인작성/관리자대리작성)
- 대리 작성 사유 (관리자 작성 시)

### 1.3 예산 항목

**구조:**
- 비목 (category)
  - 세목 (detail)
    - 품목 (item) - 선택적

**예시:**
```
비목: 운영비
  세목: 회의비
    품목: 회의실 임대료
```

### 1.4 예산서 상태

| 상태 코드 | 명칭 | 설명 |
|----------|------|------|
| `draft` | 작성 중 | 임시저장 상태 |
| `submitted` | 제출 완료 | 관리자 승인 대기 |
| `reviewing` | 검토 중 | 관리자 검토 중 |
| `revision_requested` | 보완 요청 | 보완 필요 |
| `approved` | 승인 완료 | 최종 승인 |
| `rejected` | 반려 | 승인 거부 |

### 1.5 검토 의견

**대상:**
- 예산서 전체
- 개별 예산 항목

**필드:**
- 검토자
- 검토 일시
- 의견 내용
- 종류 (전체/항목)
- 참조 항목 ID (항목 의견인 경우)

## 2. 예산 변경

### 2.1 변경 권한

- 기간이 열려있을 때만 변경 가능
- 기존 승인 예산을 덮어쓰지 않고 새 버전 생성

### 2.2 변경 이력

**보존 대상:**
- 최초 예산서
- 모든 변경 예산서

### 2.3 변경 비교

**비교 항목:**
- 신규 항목 (新增)
- 삭제 항목 (削除)
- 금액 증가 (増加)
- 금액 감소 (減少)
- 세목 변경 (変更)
- 내용 변경 (變更)

**관리자 화면:**
- 이전 예산 vs 변경 예산 비교 표
- 변경 유형별 표시 (색상 구분)

## 3. 예산 집행 현황

### 3.1 집계 대상

**단위:**
- 기업
- 사업
- 비목
- 세목

### 3.2 금액 구분

| 금액 | 설명 |
|------|------|
| 승인 예산 | 최종 승인된 예산 금액 |
| 신청 중 금액 | 구매요청/환급신청 중인 금액 |
| 미집행 승인액 | 승인됐지만 아직 집행되지 않은 금액 |
| 집행 완료 금액 | 실제 집행 완료된 금액 |
| 회계상 잔액 | 승인 예산 - 집행 완료 금액 |
| 실질 가용액 | 회계상 잔액 - 신청 중 금액 |

### 3.3 조회 화면

- 기업 사용자: 자사 집행 현황만 조회
- 관리자: 담당 사업 전체 집행 현황 조회
- 차트/그래프 지원

## 4. 구매요청 및 증빙제출

### 4.1 구매요청

**결제 방식:**
- 포스텍에서 직접 결제

**필수 정보:**
- 기업
- 요청자
- 품목
- 수량
- 단가
- 요청 금액
- 승인 금액
- 결제 금액 (실제)
- 구매처
- 세목
- 사용 내용
- 구매 일자

**상태:**
- 작성 중, 제출 완료, 검토 중, 승인 완료, 반려, 구매 완료, 증빙 대기, 증빙 완료

### 4.2 증빙제출

**규칙:**
- 구매 완료 상태인 요청에만 증빙 가능
- 기존 구매요청과 연결

**증빙 자료:**
- 세금계산서
- 계약서
- 영수증
- 기타 증빙 서류

## 5. 환급신청

### 5.1 환급 대상

- 기업
- 개인 참가자

### 5.2 필수 정보

| 항목 | 필수 여부 |
|------|----------|
| 기업 | O |
| 신청자 | O |
| 실제 환급 대상자 | O |
| 환급 요청 금액 | O |
| 관리자 승인 금액 | O (관리자 입력) |
| 실제 지급 금액 | O (관리자 입력) |
| 결제일 | O |
| 구매처 | O |
| 사용 내용 | O |
| 결제 수단 | O |
| 세목 | O |
| 증빙자료 | O |

### 5.3 환급 가능 세목

1. 인공지능 서비스 구독료
2. SaaS 구독료
3. 메타 및 인스타그램 등 홍보 집행비
4. 출장을 위한 교통비 및 숙박비
5. 회의비

### 5.4 증빙파일 명명 규칙

**시스템 생성 파일명 형식:**
```
{세목},{YYMMDD},[성장기업지원]{사용내용},{환급대상자명(기업명)},{구매처}.{확장자}
```

**예시:**
```
SaaS구독료,260711,[성장기업지원]Adobe구독,김철수(ABC테크),Adobe.kr.pdf
```

**문자 치환:**
- 파일명에 사용할 수 없는 문자는 안전한 문자로 치환
- 예: `/` → ``, `:` → `-`, `*` → ``

## 6. 환급 관리자 체크리스트

### 6.1 체크리스트 항목

| 항목 | 설명 |
|------|------|
| 개인공급업체 등록 | 포스텍 시스템에 환급 대상자가 등록되어 있는지 |
| 정산서류 제출 | 환급 대상자가 정산서류를 정확하게 제출했는지 |
| 포스텍 등록 완료 | 관리자가 포스텍 시스템에 정산서류를 등록했는지 |
| 보탬e 등록 완료 | 관리자가 보탬e 시스템에 정산서류를 등록했는지 |

### 6.2 체크 결과

| 상태 | 설명 |
|------|------|
| `pending` | 미확인 |
| `confirmed` | 확인 완료 |
| `revision` | 보완 필요 |
| `not_applicable` | 해당 없음 |

### 6.3 기록 정보

- 확인 관리자
- 확인일시
- 관리자 메모

### 6.4 데이터 구조

**설계 원칙:**
- 체크리스트 항목을 DB 컬럼으로 고정하지 않음
- 항목 정의 테이블 (`checklist_items`)와 결과 테이블 (`checklist_results`) 분리

## 7. 이메일 알림

### 7.1 사용자 대상 이메일

| 이벤트 | 템플릿 |
|--------|--------|
| 신청 완료 | `application_submitted` |
| 보완 요청 | `revision_requested` |
| 승인 완료 | `application_approved` |
| 반려 | `application_rejected` |
| 집행 완료 | `payment_completed` |
| 프로그램 신청 완료 | `program_applied` |
| 참가 승인 | `participation_approved` |
| 참가 완료 | `participation_completed` |
| 참가 확인서 발급 | `certificate_issued` |

### 7.2 관리자 대상 이메일

| 이벤트 | 템플릿 |
|--------|--------|
| 구매요청 제출 | `purchase_request_submitted` |
| 구매 증빙자료 제출 | `proof_document_submitted` |
| 환급신청 제출 | `refund_application_submitted` |
| 보완자료 재제출 | `revision_resubmitted` |
| 예산서 제출 | `budget_submitted` |
| 변경 예산서 제출 | `budget_change_submitted` |
| 프로그램 참가 신청 | `program_application_received` |

### 7.3 이메일 발송 규칙

**발송 상태:**
- `pending` - 대기 중
- `sent` - 발송 완료
- `failed` - 발송 실패

**실패 사유:**
- 수신자 이메일 없음
- 발송 서비스 오류
- 기타

**설계 원칙:**
- 상태 변경과 이메일 발송을 강하게 결합하지 않음
- 별도의 발송 작업과 발송 이력으로 재시도 가능

## 8. 프로그램 운영

### 8.1 프로그램 게시

**관리자 기능:**
- 임시저장
- 게시
- 공개/비공개 전환

**발송 분리:**
- 게시와 전체 메일 발송은 별도 동작

### 8.2 신청서 질문 구성

**지원 질문 유형:**

| 유형 | 설명 |
|------|------|
| short_text | 짧은 텍스트 |
| long_text | 긴 텍스트 (textarea) |
| number | 숫자 |
| date | 날짜 |
| single_choice | 단일 선택 (radio) |
| multiple_choice | 복수 선택 (checkbox) |
| file_upload | 파일 업로드 |

**프로그램별 구성:**
- 각 프로그램마다 다른 질문 구성 가능

### 8.3 신청 상태

| 상태 코드 | 명칭 | 설명 |
|----------|------|------|
| `draft` | 작성 중 | 임시저장 |
| `submitted` | 신청 완료 | 제출 완료 |
| `reviewing` | 검토 중 | 관리자 검토 중 |
| `approved` | 참가 승인 | 참가 승인 |
| `waitlisted` | 대기 | 대기자 |
| `rejected` | 반려 | 신청 반려 |
| `cancelled` | 취소 | 신청 취소 |
| `completed` | 참가 완료 | 프로그램 참가 완료 |
| `no_show` | 불참 | 불참 |

### 8.4 참가 확인서

| 항목 | 필수 |

| 소속 | O |
| 프로그램명 | O |
| 운영 일시 | O |

## 9. 예산 가이드라인 및 챗봇

### 9.1 가이드라인 관리

**관리자 기능:**
- 등록
- 수정
- 공개/비공개

**버전 관리:**
- 버전 번호
- 시행일

### 9.2 챗봇 (RAG 방식)

**동작 방식:**
- 관리자가 등록한 가이드라인 검색
- FAQ 검색
- 근거 문서 기반 답변

**답변 구성:**

| 항목 | 설명 |
|------|------|
| 가능 여부 | 집행 가능 여부 (확정/조건부/불가/관리자확인필요) |
| 권장 세목 | 적합한 세목 추천 |
| 신청 방식 | 구매요청/환급신청 |
| 필요 증빙 | 필요한 증빙 서류 |
| 주의사항 | 유의사항 |
| 근거 문서 | 근거가 된 가이드라인/FAQ |
| 관리자 확인 필요 | 관리자 추가 확인 필요 여부 |

**주의사항:**
- 근거를 찾지 못하면 확정적으로 답변하지 않음
- 관리자 문의 안내

## 우선순위

### 1순위 (MVP)
- 사용자 인증/권한
- 예산서 작성 및 승인
- 구매요청 및 승인
- 기본 화면 구조

### 2순위
- 환급신청 및 승인
- 프로그램 운영 기본 기능
- 이메일 발송

### 3순위
- 예산 변경
- 집행 현황 조회
- 참가 확인서 발급

### 4순위
- 가이드라인/챗봇
- 고급 리포팅
- 통계 기능
